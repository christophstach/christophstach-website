# Project Agent Instructions

- Activate the `orchestrator` skill (`.agents/skills/orchestrator/SKILL.md`) for multi-step workflows, parallel edits, larger features or refactors, structured research/brainstorming, or risky changes. Simple, straightforward 1–2 file edits with no parallel work or risk gates may be handled directly (or in `LIGHT` orchestration mode).
- When operating inside an orchestrated run, use **Hybrid Delegation**: the orchestrator may directly run deterministic Git lifecycle commands (ref checks, worktrees, merges, push, cleanup), quick planning lookups (up to ~3 small reads), log-redirected programmatic checks (`verify`), and small self-improvement edits to `.agents/skills/orchestrator/SKILL.md`. Always delegate actual repo implementation, broad codebase research/brainstorming, and independent QA to worker subagents defined with `enable_subagent_tools: false` in isolated Git worktrees.
- **Delivery Mode (`delivery_mode: direct_main`):** In this repository, direct delivery to `main` is preferred—do not create extra pull requests unless explicitly requested. During orchestrated work, still isolate active edits in temporary worktrees so `main` stays clean while work is in progress. Once all verification gates pass, fast-forward/merge directly into `main`, push to `origin/main`, and clean up temporary worktrees and `orch/<run_id>/*` branches.
- Never force-push (`--force`) or rewrite history on `main`, and always pause with a clear, non-cryptic, plain-language decision (preferring `ask_question`, matching the user's language, and hiding internal IDs/rule codes) for unapproved breaking changes, public API or schema edits, new dependencies, destructive operations, or merge conflicts.
- Keep `.worktrees/` ignored in `.gitignore`.
